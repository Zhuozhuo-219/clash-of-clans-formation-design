# 外部模型生成阵型草案的提示词模板

把以下文字发送给能访问本仓库资料的 ChatGPT 或其他模型：

> 我在设计中国大陆服务器的18本部落战防三星阵型。请先读取 `data/catalog.json` 和 `schemas/coc-th18-draft-v1.schema.json`，严格使用44×44坐标，建筑的占地和数量以目录为准。不要使用5×5兵营/攻城机器工坊；这两者和大本营、英雄殿堂都是4×4。陷阱、隐藏特斯拉不扩展禁下兵圈。先安排大本营、部落城堡、反击之塔、擎天巨柱和主要防御的初始骨架，并给出可解释的偏置和分散理由。请只提交格式为 `coc-th18-draft-v1` 的 JSON 草案，不要使用不存在的建筑，不要重叠；可使用少量 `autoFill` 让工具放置防空建筑。保存到 `drafts/` 并先运行仓库的 `node scripts/layout-cli.mjs validate <文件>`，不通过则修改并再次验证。提示词中不明确的数据必须标记为未知，不得捏造国服精确战斗值。

一条实际示例指令：

> 帮我生成偏置大本营、分散防空和中后期保留反击之塔的18本防三星**骨架**。先只设计10—25个建筑和少量陷阱，不用急着填完整墙体。使用仓库工具检查后提交 JSON。

## 使用原则

1. 模型解析自然语言，负责“方向和构想”；非确定性的规则不得当成唯一最优解。
2. 仓库 CLI 负责验证硬约束并可执行部分自动补位。模型看错误日志反复纠正。
3. 编辑器人工核对，之后依靠国服友谊战、回放改进。当前未构建高精度寻路或战斗模拟。
4. 此 JSON 是**研究编辑器的数据协议**，不是官方客户端的布局链接/API。
