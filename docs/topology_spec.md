# 44×44下兵线拓扑基线 v0.1

**目标**：给出可检查、可复用的「结构占格 / 禁下兵区域 / 白线拓扑」定义，避免先引入攻击寻路与阵型评分。

## A. 坐标与占格

地图逻辑域 `G={(x,y) | x,y均为整数，0≤x<44，0≤y<44}`。坐标原点是二维矩阵左上角，跟游戏画面菱形朝向无关。

每个对象 `o={uid,id,x,y}` 的占地 `F(o)=[x,x+w)×[y,y+h)`。`w,h`取自 `catalog.json`。普通建筑、城墙、特斯拉与陷阱都参与**物理占位冲突检测**。在此版本只能放在44×44矩形内；真实可建设掩码仍未确认。

## B. 形成禁止下兵的区域

定义 `S` 为已摆放的普通建筑与城墙集合，**不含隐藏特斯拉和陷阱**。每个 `o∈S` 产生：

```
D(o) = { (x,y)∈Z² | x_o−1 ≤ x ≤ x_o+w_o,
                        y_o−1 ≤ y ≤ y_o+h_o }
D = ⋃ D(o)
D_G = D ∩ G
```

相当于每个矩形 `F(o)` 以 8 邻域（Chebyshev 半径1）作一次形态学膨胀，再取所有禁区并集。这个版本的**静态下兵候选集合**为 `G \ D_G`。对地图外区域不宣称绝对合法/非法，因为地图外边界和游戏下兵地形仍待核验。

**特别注意**：特斯拉、陷阱的占格可以落在 `G \ D_G` 内，表示其所在的格子不会自动禁止敌方下兵；不代表玩家能在布局编辑器内将建筑互相重叠。

## C. 白线与内部空洞

白线是 `D` 的单位格边界：每个禁区格子，检查其上、右、下、左4个邻格。邻格不在 `D`，则相邻的整条单位网格边即为白线的一段。白线既可以包围外形，也可包围内部空洞，可能是多个互不连接的闭合轮廓。

将 `G \ D_G` 依上下左右4邻接做连通分量分析。某个允许下兵连通分量如果不接触44×44边缘，暂称**内部下兵空洞**。它并非被禁止下兵：恰好相反，它是防守方应该关注的潜在内点下兵风险；应在地图中着黄色。连通性主要用于静态拓扑分类，不等同于单位真实路径连通性。

## D. 最小测试

1. 单独4×4大本营放在(10,10)：6×6=36格形成禁下兵集合；外围轮廓24条单位边。
2. 单独隐藏特斯拉(10,10)与巨型炸弹(13,13)：禁下兵集合0格，但摆放碰撞依然生效。
3. 两段墙放(10,10)和(13,10)：中间2格均禁下兵。若墙改放(14,10)，中间3格中的中间格允许下兵。
4. 宽阔闭合墙圈：中心如离任一墙至少2格，可能成为内点下兵空洞；小圈内部可能完全被一格膨胀覆盖。
5. 对同一对象的移动不应触发重复数量限制，目标位与其它对象重叠必须被拒绝。

## E. 已知边界与后续核实

- 取 `D(o)` 的1格扩张是根据公开社区资料和当前项目设计需求形成的*静态假设*；可通过国服布局编辑器与进攻截图逐格核对。
- `buildable_mask`、四角不可摆放区域、地图最外圈的实际放兵规则、某些特殊建筑、障碍或动态机制未核实。
- 不对英雄防守守卫、精制防御激活、地图多层、单位占地、瞄准、攻击间隔、持续伤害做推演。
- 修改源数据时，以正式国服客户端核实结果为最终依据；保留当前实现版本作回归测试。

## F. 核心接口

```js
const CATALOG = Object.fromEntries(catalog.objects.map(a=>[a.id,a]));
const mask = TH18Topology.deploymentMask(objects,CATALOG,44);
const lineSegments = TH18Topology.boundaryEdges(mask);
const state = TH18Topology.deploymentStatus(x,y,mask,44);
const allRegions = TH18Topology.allowedRegions(mask,44);
const check = TH18Topology.placementCheck(objects,CATALOG,{uid,id,x,y});
const totals = TH18Topology.stats(objects,CATALOG,44);
```
